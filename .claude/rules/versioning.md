# バージョン運用

番号の決定はユーザーから **Claude に委任**されている（2026-08-05）。ただし破壊的変更が絡む場合と、CRAN 提出時期そのものを動かす判断はユーザーに確認する。

## 2 つのチャンネル

| チャンネル | 実体 | 版の確認方法 |
|---|---|---|
| 開発版 | GitHub main（`pak::pak("yo5uke/coresynth")`） | DESCRIPTION の `Version:` |
| リリース | CRAN | https://cran.r-project.org/package=coresynth（**推測せず必ず参照する**） |

DESCRIPTION の版は GitHub に push した時点で「開発版として公開済み」になる。CRAN 公開とは別物として扱う。

## 判断手順（DESCRIPTION の `Version:` を触る前に必ず実行）

1. CRAN 現行版と公開日を確認する
2. DESCRIPTION の現在値が CRAN 公開済みかどうかを見る
   - **未公開（GitHub 先行中）** → **番号は据え置き**。NEWS.md も同じ見出しに追記する。開発中に都度番号を刻み直さない（ユーザーの意向: 番号を確定させるたびにすぐ次の更新が来て刻み直す羽目になる）
   - **公開済み** → 新しい番号を決める（次節）
3. CRAN 提出を伴うなら、直近の CRAN 公開日から 1〜2 ヶ月空いているかを確認する。空いていなければ提出時期をユーザーに確認する（CRAN Repository Policy の更新頻度）

## 番号の決め方（CRAN 公開済みの版に対して）

- **patch `x.y.Z`** — バグ修正・性能改善・内部変更のみ。ユーザーから見た API と引数が不変
- **minor `x.Y.0`** — 新機能・新引数・新 export（後方互換）
- **major `X.0.0`** — 破壊的変更（既定値の変更を含む）

マイナーを上げるときは `.0` から始める。`0.1.2 → 0.2.1` のように `.0` を飛ばすと「存在しない 0.2.0 への修正」に読めるため避ける（CRAN 的には合法だが紛らわしい）。

## `.9000` 開発版サフィックス

未公開のまま番号を据え置くと、GitHub 版利用者が「同じ番号で違う中身」を掴む。次のどちらかに該当したら `.9000` に移す:

- 据え置き期間中に中身がまとまって変わり、その間に GitHub 版が使われる可能性がある
- 破壊的変更・大きな機能が入り、提出時の番号が現在値では足りないと確定した

付け方は直近で **GitHub に出した番号**に `.9000`（例 `0.5.0` → `0.5.0.9000`）、NEWS.md の見出しは `# coresynth (development version)`。提出時は `.9000` を落として元の番号に戻すのではなく、**次の番号へ上げる**（`0.5.0.9000` → `0.6.0` / `0.5.1`）。戻すと GitHub 版から見てダウングレードになる。CRAN に出ないまま終わる番号があっても構わない。

## CRAN 側の外形的制約

- 提出版は CRAN 現行版より**厳密に大きい**こと。連番である必要はなく、間の番号が存在しなくてよい（`0.4.1 → 0.5.0` で `0.4.2` が欠番でも問題ない）
- 比較は成分ごとの数値比較。`0.4.9 < 0.4.10 < 0.5.0 < 0.5.0.9000 < 0.5.1`
- 公開済みバージョンの上書き・番号の再利用は不可（旧版は Archive に残る）
- 却下されて未公開のままなら、**同じ番号で再提出してよい**

## リリース時のチェックリスト

1. `NEWS.md` の見出しを確定番号にし、内容が実装と一致しているか確認
2. `DESCRIPTION` の `Version:` を更新（`RoxygenNote: 8.0.0` が書き戻されていないかも確認）
3. `devtools::document()` → `build-install` skill → `devtools::test()`
4. `devtools::check(args = c("--no-manual", "--run-donttest"))` で 0 errors / 0 warnings / 0 notes
5. 新規 export・S3 method があれば `pkgdown-check` skill
6. コミットは「機能」と「`chore(release): bump version to x.y.z`（DESCRIPTION + NEWS.md）」に分ける
